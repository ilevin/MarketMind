## Why

当前 v0.2.0 首次部署要求运维在启动服务前通过 CLI 设置管理员密码，首次使用门槛较高，也不符合普通用户“打开页面即可完成初始化”的使用预期。将首个用户创建改为首次访问时的受控引导，可以简化全新部署流程，同时让该用户直接成为系统管理员。

## What Changes

- 新增首次访问初始化页面，引导匿名用户填写第一个用户的用户名和密码。
- 当系统不存在任何用户时，允许匿名提交一次首用户创建请求；创建的用户自动获得 `admin` 角色并可立即登录。
- 初始化完成后关闭匿名首用户创建入口；后续账户仍只能由管理员或 CLI 创建，保留现有公开注册关闭策略。
- 未完成初始化时，匿名访问系统页面/API 应被引导到初始化流程；已完成初始化后继续使用现有登录和授权行为。
- 首用户创建需复用现有用户名校验、密码 Argon2id 哈希、CSRF/会话安全和写锁约束，并处理并发初始化请求，确保最多创建一个首用户。
- 更新 v0.2.0 的部署说明，说明全新部署可通过首次访问完成初始化；保留旧数据库升级后 legacy owner/已有用户的兼容路径。

## Capabilities

### New Capabilities

- `first-visit-onboarding`: 定义空用户库首次访问时创建第一个管理员用户的页面、接口、状态转换和安全约束。

### Modified Capabilities

- `user-authentication`: 增加未初始化状态、初始化页面/接口及初始化完成后的访问与登录行为。
- `user-management`: 调整“首个管理员必须通过 CLI 创建”的初始化要求，并明确首访创建的管理员用户仍遵守用户名、密码和管理员保护规则。
- `deployment`: 更新全新部署的管理员初始化步骤和升级场景说明。
- `db-migration`: 将升级后的 legacy owner 初始化改为优先通过 `/setup` 认领，并保留停服后的 CLI 后备路径。

## Impact

- 认证与用户管理路由、依赖和服务：新增初始化状态判断、首用户创建接口及页面跳转逻辑。
- 用户创建服务、用户仓储和数据库写入路径：复用校验与哈希逻辑，并保证并发请求下的单次初始化。
- 登录/首页模板及前端脚本：新增首次访问引导页面和表单错误处理。
- 测试：补充空库首访、成功初始化、重复/并发提交、初始化后拒绝匿名创建、已有用户/升级库兼容等场景。
- README 与部署/迁移规格：移除全新部署必须先手动设置管理员密码的前置步骤；旧版本升级优先通过 `/setup` 以自定义用户名认领 legacy owner，停服后的 CLI 仅作为后备路径。
